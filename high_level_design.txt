### 1.2 Technology Stack
- **Framework**: Express.js with TypeScript
- **Authentication**: jsonwebtoken, passport.js
- **Rate Limiting**: Redis with ioredis client
- **Message Queue**: KafkaJS
- **Validation**: Joi or Zod
- **Logging**: Winston or Pino
- **Metrics**: prom-client (Prometheus)
- **HTTP Client**: Axios (for Service Registry)
- **Testing**: Jest, Supertest

## 2. API Endpoints

### 2.1 Message APIs
```typescript
POST   /api/v1/messages/send         // Send single/multi-channel message
POST   /api/v1/messages/bulk         // Bulk message sending
GET    /api/v1/messages/:id          // Get message status
GET    /api/v1/messages/:id/events   // Get message events
```


## 3. Core Components Design

### 3.1 Authentication Service
```typescript
interface AuthService {
  validateJWT(token: string): Promise<JWTPayload>;
  validateAPIKey(key: string): Promise<Tenant>;
  verifyWebhookSignature(
    channel: string,
    signature: string,
    body: any
  ): Promise<boolean>;
}

interface JWTPayload {
  tenantId: string;
  userId: string;
  permissions: string[];
  exp: number;
}
```

### 3.2 Rate Limiter Service
```typescript
interface RateLimiterService {
  checkLimit(key: string, limit: number): Promise<RateLimitResult>;
  consumeToken(key: string): Promise<void>;
  getRemainingTokens(key: string): Promise<number>;
}

interface RateLimitResult {
  allowed: boolean;
  remaining: number;
  resetAt: Date;
  retryAfter?: number;
}

// Rate limit keys structure:
// - rate:tenant:{tenantId}:total
// - rate:tenant:{tenantId}:channel:{channel}
// - rate:tenant:{tenantId}:endpoint:{endpoint}
```

### 3.3 Kafka Producer Service
```typescript
interface KafkaProducerService {
  publishMessage(topic: string, message: any): Promise<void>;
  publishBatch(topic: string, messages: any[]): Promise<void>;
  publishWithRetry(
    topic: string, 
    message: any, 
    retries?: number
  ): Promise<void>;
}

// Topics:
// - message.channel.route.{channel}
// - message.bulk.route.{channel}
// - conversation.events
// - webhook.received.{channel}
```

### 3.4 Validation Service
```typescript
interface ValidationService {
  validateSendMessage(body: any): SendMessageDTO;
  validateBulkMessage(body: any): BulkMessageDTO;
  validateWebhook(channel: string, body: any): WebhookDTO;
}

// DTOs with strict typing
interface SendMessageDTO {
  to: string | string[];
  channel: ChannelType;
  content: MessageContent;
  tenantId?: string;
  conversationId?: string;
  metadata?: Record<string, any>;
}
```

## 4. Request Processing Flow

### 4.1 REST API Flow
```
1. Request arrives at Express route
2. Global error handler wraps request
3. Correlation ID middleware adds traceId
4. Authentication middleware validates JWT/API key
5. Extract tenant context from token
6. Rate limiting check (Redis)
7. Request validation (Joi/Zod)
8. Business logic in controller
9. Publish to Kafka
10. Return response with messageId
```

### 4.2 Webhook Flow
```
1. Webhook POST received
2. Verify webhook signature (channel-specific)
3. Parse channel-specific payload
4. Transform to standard format
5. Publish to Kafka (webhook.received topic)
6. Return 200 OK immediately
```

## 5. Error Handling Strategy

### 5.1 Error Types
```typescript
class ValidationError extends Error {
  statusCode = 400;
  errors: ValidationErrorDetail[];
}

class AuthenticationError extends Error {
  statusCode = 401;
  code: 'INVALID_TOKEN' | 'EXPIRED_TOKEN' | 'NO_TOKEN';
}

class RateLimitError extends Error {
  statusCode = 429;
  retryAfter: number;
  resetAt: Date;
}

class ServiceUnavailableError extends Error {
  statusCode = 503;
  service: string;
  retryAfter?: number;
}
```

## 6. Security Considerations

### 6.1 Security Measures
- **JWT validation** with RS256 algorithm
- **API key rotation** support
- **Webhook signature verification** per channel
- **Request size limits** (10MB default)
- **SQL injection prevention** via parameterized queries
- **XSS protection** headers
- **CORS configuration** with whitelist
- **Helmet.js** for security headers

### 6.2 Rate Limiting Strategy
```
Hierarchical Rate Limiting:
1. Global limit: 1000 r/s (total service)
2. Per-tenant limit: 50 r/s (across all channels)
3. Per-tenant-channel: 50 r/s
4. Per-endpoint limit: Custom limits
5. Bulk endpoint: 10 r/s with larger payloads
```

## 9. Deployment Considerations

### 9.1 Container Setup
```dockerfile
FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production
COPY . .
RUN npm run build
EXPOSE 3000
CMD ["node", "dist/index.js"]
```

### 9.2 Health Checks
- **Liveness**: Basic health check
- **Readiness**: Checks Redis, Kafka, Service Registry connections

### 9.3 Scaling Strategy
- Horizontal scaling with multiple instances
- Load balancer in front (nginx/ALB)
- Sticky sessions not required (stateless)
- Auto-scaling based on CPU/memory/request rate
